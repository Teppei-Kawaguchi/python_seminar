# 第9回Python Seminar：コードの流れを理解する初心者向けガイド

## 1. この資料の目的

この資料は、[第9回_Python_Seminar.ipynb](./第9回_Python_Seminar.ipynb)で「何を、どの順番で、なぜ行っているか」を初心者向けに説明したものです。

今回の課題を一文で表すと、次のようになります。

> 分子を文字で表したSMILESから、分子の`gap_eV`を予測し、答えのない4,000分子について予測結果を提出する課題です。

Notebookを発表するときは、細かいコードを上から全部読む必要はありません。まず全体の流れを理解し、その後で各処理の役割を確認してください。

## 2. 全体の流れ

```text
指定CSVを読む
    ↓
列・行数・欠損を確認する
    ↓
SMILESを数値の特徴量へ変換する
    ↓
trainを同じ条件の5組に分ける
    ↓
単純なbaselineを計算する
    ↓
Extra TreesとXGBoostを学習する
    ↓
train内のOOF MAEでモデルを比較する
    ↓
選んだモデルを全trainで学び直す
    ↓
test 4,000件を予測する
    ↓
submission.csvを保存して検査する
```

この順番で進める理由は、testの答えを見ずにモデルを選び、未知データに対する性能を公平に見積もるためです。

## 3. 使用するデータ

| ファイル | 行数 | 列 | 役割 |
| --- | ---: | --- | --- |
| `qm9_bandgap_train.csv` | 15,000 | `smiles`, `gap_eV` | モデルの学習と検証に使う |
| `qm9_bandgap_test_without_answer.csv` | 4,000 | `smiles` | 最後に`gap_eV`を予測する |

- `smiles`は、分子の原子や結合を1行の文字列で表したものです。
- `gap_eV`は今回予測する数値です。
- `eV`はエネルギーの単位です。
- testには正解の`gap_eV`がありません。

## 4. 最初にライブラリと設定を読み込む

### 何をしているか

CSV、数値計算、グラフ、特徴量作成、モデル学習に必要なライブラリを読み込みます。その後、データの場所、乱数seed、fold数、特徴量の大きさ、モデルの設定を変数へ保存します。

### なぜ設定を1か所へまとめるか

設定が複数のセルへ分散すると、変更忘れが起こりやすくなります。Notebookでは、主な設定を序盤の1セルへまとめています。

### 初心者が確認する値

- `SEED = 8`：乱数を固定し、同じ条件で結果を再現するための値
- `TARGET = "gap_eV"`：予測する列名
- `N_SPLITS = 5`：trainを5組に分ける指定
- `FEATURE_MODE = "auto"`：RDKitの有無に応じて特徴量方式を選ぶ指定
- `N_FINGERPRINT_FEATURES = 2048`：fingerprintまたはhash特徴量の列数

## 5. データを読み、安全性を確認する

### 入力

指定されたtrain CSVとtest CSVです。

### 処理

`pd.read_csv()`でCSVを読み、`assert`で次の条件を確認します。

- trainが15,000行か
- testが4,000行か
- trainの列順が`smiles, gap_eV`か
- testが`smiles`列だけか
- SMILESや`gap_eV`に欠損がないか
- `gap_eV`にNaNや無限大がないか
- testへ正解列が混ざっていないか

### なぜ`assert`を使うか

`assert`は、想定と違うデータを使ったときに処理をその場で止める安全装置です。間違った列順や行数のまま学習が進むことを防ぎます。

## 6. データの特徴を確認する

次の内容を表とグラフで確認します。

- 欠損セル数
- SMILESのユニーク数と重複数
- trainとtestで完全一致するSMILES数
- `gap_eV`の平均、中央値、最小値、最大値
- SMILES文字列の長さ
- フッ素`F`を含む分子数

今回のデータでは、trainにFを含む分子がありますが、testにはありません。そのため、通常のOOF MAEに加え、train内の非F分子だけのMAEも補助的に確認します。

## 7. SMILESをモデルが扱える数値へ変換する

機械学習モデルへSMILES文字列をそのまま渡すのではなく、数値の表へ変換します。この数値を**特徴量**と呼びます。

### 7.1 RDKitがある場合

- RDKitの2D分子記述子
- Morgan fingerprint

を作ります。分子記述子は分子全体の性質、fingerprintは分子中の部分構造を数値で表します。

### 7.2 RDKitがない場合

現在の検証環境ではRDKitを利用できないため、次のfallback特徴量を使っています。

- SMILESの文字数
- 原子記号の数
- 炭素、窒素、酸素、フッ素などの数
- 二重結合や三重結合の数
- 分岐や環を表す記号の数
- SMILES中の1〜5文字の並びを2048列へ変換したhash特徴量

### 重要な注意

fallbackの文字n-gram hash特徴量は、Morgan fingerprintではありません。発表では、実行結果の`Feature mode`を確認して、実際に使った方式を説明します。

## 8. 同じ分子を分離しない5-foldを作る

### 5-foldとは

trainを5組に分け、4組で学習し、残り1組で性能を確認する方法です。確認に使う組を入れ替えて、合計5回学習します。

### このNotebookでの工夫

- `gap_eV`の分布がfold間で大きく変わらないようにする
- 同じSMILESを学習側と検証側の両方へ入れない
- seedを8に固定して毎回同じ分け方を使う

同じ分子が学習側と検証側の両方へ入ると、モデルが一度見た分子を予測することになり、性能が実際より良く見える可能性があります。これを防ぐことが重要です。

## 9. baselineを計算する

baselineは、複雑なモデルを使わない基準値です。

各foldの学習部分で`gap_eV`の中央値を求め、検証部分の全行へ同じ中央値を予測します。今回のbaseline OOF MAEは次の値です。

| 方法 | OOF MAE |
| --- | ---: |
| 学習fold中央値 | 1.075058 eV |

Extra TreesやXGBoostがこの値より良ければ、特徴量から予測に役立つ規則を学べたと判断できます。

## 10. Extra Treesを学習する

### モデルの考え方

Extra Treesは、異なる多数の決定木を作り、その予測を平均するモデルです。1本の木だけに頼らないことで、予測のばらつきを抑えます。

### 使用する特徴量

Extra Treesには、説明しやすい分子記述子だけを入力します。

### 調整後のハイパーパラメータ

| パラメータ | 値 | 初心者向けの意味 |
| --- | ---: | --- |
| `n_estimators` | 600 | 600本の木を作って平均する |
| `max_features` | 0.85 | 各分岐で特徴量の85%を候補にする |
| `min_samples_leaf` | 4 | 1つの葉に最低4件を残す |
| `bootstrap` | `True` | 重複を許して学習行を抽出する |
| `max_samples` | 0.80 | 各木では学習foldの80%を使う |

`min_samples_leaf`を1から4へ増やすことで、少数の分子だけに合わせた細かすぎる分割を減らしました。

## 11. XGBoostを学習する

### モデルの考え方

XGBoostは、前の木が間違えた部分を次の木で少しずつ修正するモデルです。この修正を多数回繰り返します。

### 使用する特徴量

XGBoostには、分子記述子と2048列のfingerprintまたはhash特徴量を結合して入力します。

### 調整後の主なハイパーパラメータ

| パラメータ | 値 | 初心者向けの意味 |
| --- | ---: | --- |
| `n_estimators` | 1,000 | 1,000本の木で少しずつ予測を修正する |
| `learning_rate` | 0.03 | 1本ごとの修正量を3%に抑える |
| `grow_policy` | `lossguide` | 誤差を大きく減らす葉から優先して分ける |
| `max_depth` | 0 | 深さでは制限せず、葉の数で制限する |
| `max_leaves` | 128 | 1本の木の葉を最大128個にする |
| `min_child_weight` | 2 | データが少なすぎる分岐を作りにくくする |
| `subsample` | 0.90 | 各木で学習行の90%を使う |
| `colsample_bytree` | 0.90 | 各木で特徴量の90%を使う |
| `reg_alpha` | 0.02 | 葉の値が複雑になりすぎることを抑える |
| `reg_lambda` | 5.0 | 葉の値が極端になることを抑える |

深さ6へ固定した元の設定より、良い葉を優先する`lossguide`と最大128葉の組み合わせが有効でした。

## 12. ハイパーパラメータを調整した流れ

調整ではtestの正解を使っていません。固定したtrain内foldだけを使用しました。

### Extra Trees

1. 木を200本にそろえ、`max_features`、`min_samples_leaf`、`max_depth`を広く比較
2. 良かった葉サイズ3〜6を木300本で比較
3. 上位候補を木600本の正式5-foldで再比較
4. `min_samples_leaf=4`、bootstrap、80%抽出を採用

### XGBoost

1. 深さ5〜8、学習率、子ノード条件、行・列の使用割合、正則化を代表2-foldで比較
2. 深さ固定と`lossguide`の最大64葉・128葉を比較
3. 128葉が良かったため、木の本数を1,000本まで確認
4. 最終候補を正式な全5-foldで再確認

### 調整結果

| モデル | 調整前 | 調整後 | 改善率 |
| --- | ---: | ---: | ---: |
| Extra Trees | 0.466661 eV | 0.442752 eV | 約5.1% |
| XGBoost | 0.307848 eV | 0.249353 eV | 約19.0% |

候補を試しすぎると、同じCVへ偶然合った設定を選ぶ危険があります。そのため、意味を説明できる主要パラメータに絞り、粗い比較から細かい比較へ進めました。

## 13. OOF予測でモデルを比較する

### OOF予測とは

各train行を、その行を学習に使っていないモデルで予測した値です。英語ではOut-of-Fold predictionと呼びます。

### 評価指標MAE

MAEは、予測値と正解値の差の絶対値を平均したものです。

```text
MAE = |正解値 - 予測値| の平均
```

値が小さいほど、平均的な予測のずれが小さいことを表します。単位は目的変数と同じeVです。

### 調整後の正式結果

| モデル | OOF MAE |
| --- | ---: |
| XGBoost | 0.249353 eV |
| Extra Trees | 0.442752 eV |
| 中央値baseline | 1.075058 eV |

Extra TreesとXGBoostの予測を混ぜる比率もOOF予測だけで比較しました。最良のXGBoost重みは1.00だったため、最終候補はXGBoost単体になりました。

> 0.249353 eVはtrain内のOOF MAEです。答えなしtestの最終MAEではありません。

## 14. 予測グラフと残差を見る

Notebookでは次の2枚のグラフを表示します。

1. 実測値とOOF予測値の散布図
2. 残差のヒストグラム

散布図では、点が斜めの基準線に近いほど良い予測です。残差は`実測値 - 予測値`で、0付近に集まるほど誤差が小さいことを表します。

## 15. 全trainで学び直し、testを予測する

ハイパーパラメータと採用モデルをOOFだけで決めた後、次の処理を行います。

1. 補完器を全trainで学習する
2. Extra Treesを全trainで学習する
3. XGBoostを全trainで学習する
4. test 4,000件を予測する
5. OOFで選ばれたXGBoost予測を提出用に使う

test特徴量をモデルへ入力するのはこの段階です。testはハイパーパラメータ選択には使いません。

## 16. submission.csvを作り、検査する

提出ファイルは次の形式です。

| 列 | 内容 |
| --- | --- |
| `smiles` | 元testと同じSMILES、同じ順番 |
| `gap_eV` | XGBoostが予測した値 |

保存前と保存後の両方で、次の内容を`assert`で確認します。

- 列名と列順が`smiles, gap_eV`か
- 4,000行か
- SMILESの内容と順番が元testと一致するか
- `gap_eV`が数値型か
- NaNや無限大がないか

完成するファイルは[submission.csv](./submission.csv)です。

## 17. 特徴量重要度を確認する

最終XGBoostが予測時によく利用した特徴量を上位20個表示します。

ただし、重要度が高い特徴量が`gap_eV`の物理的な原因だとは限りません。特徴量重要度はモデル内での利用度であり、因果関係の証明ではありません。

## 20. 初心者向けの説明例

> 今回は、分子を文字で表したSMILESからgap_eVを予測しました。学習データ15,000件を5組に分け、4組で学習して残り1組を予測する作業を5回行いました。これにより、testの答えを使わずにモデルを比較できます。Extra TreesとXGBoostの設定を調整した結果、XGBoostのOOF MAEが0.307848 eVから0.249353 eVへ改善しました。最後にXGBoostを全学習データで学び直し、test 4,000件の予測をsubmission.csvへ保存しました。

## 21. よくある間違い

- OOF MAEをtestの最終成績と言う
- testの正解を見てハイパーパラメータを変更する
- fallback特徴量をMorgan fingerprintと呼ぶ
- 同じSMILESを学習側と検証側へ分ける
- 欠損補完を全データでfitしてからCVする
- モデル名だけを見て、同じfoldで比較しない
- `submission.csv`のSMILES順を並べ替える
- 特徴量重要度を物理的な原因だと断定する
