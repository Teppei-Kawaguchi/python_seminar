## 2. 課題の結論

与えられた分子の `smiles` から数値特徴量を生成し、学習データだけを使って `gap_eV` を予測する回帰モデルをゼロから学習する。テストデータ4,000件に対する予測を `submission.csv` に保存し、正解値とのMAE（Mean Absolute Error）を小さくすることが課題の中心である。

同時に、QM9、RDKit、SMILES、分子記述子、フィンガープリントを説明できるようにし、使用モデルと工夫点を約1分で口頭説明する。

成功条件は次の4点である。

1. レギュレーションに違反しない。
2. 学習データ内の検証だけでモデルとハイパーパラメータを決める。
3. テスト4,000件と同じ順序で、指定列を持つ有効な `submission.csv` を作る。
4. 特徴量、モデル、検証MAE、工夫点を簡潔に説明できる。

## 6. 用語の整理

### QM9

QM9は、小さな有機分子について量子化学計算された構造・物性を収録したデータセットである。原論文では、C、H、O、N、Fからなる133,885分子、重原子数最大9、B3LYP/6-31G(2df,p)レベルで計算された物性が報告されている。

今回のファイルはQM9全体ではなく、train 15,000件とtest 4,000件からなる課題用部分集合である。外部のQM9全体を追加学習に使うことは「データ追加不可」に反する。

参考：[Ramakrishnan et al., “Quantum chemistry structures and properties of 134 kilo molecules”](https://www.nature.com/articles/sdata201422)

### RDKit

RDKitはオープンソースの化学情報学ツールキットである。SMILESの読み込み、分子構造の検証・正規化、分子記述子、Morgan fingerprintなどの生成に利用できる。この課題では「SMILESを機械学習用の数値特徴量へ変換する部分」を主に担当する。

参考：

- [RDKit Python入門](https://www.rdkit.org/docs/GettingStartedInPython.html)
- [RDKitの分子記述子API](https://www.rdkit.org/docs/source/rdkit.Chem.Descriptors.html)

### SMILES

SMILES（Simplified Molecular Input Line Entry System）は、原子と結合からなる分子グラフを1行の文字列で表す記法である。例えば、括弧は分岐、数字は環の閉環、`=` や `#` は多重結合を表す。

同一分子に複数の正しいSMILES表現が存在し得るため、単なる文字列一致だけでは同一分子判定として不十分な場合がある。RDKitでcanonical SMILESへ変換し、重複や分割漏洩を再確認する。

参考：[Daylight SMILES Theory Manual](https://www.daylight.com/dayhtml/doc/theory/theory.smiles.html)

### 分子記述子

一つの分子を、分子量、原子数、環数、回転可能結合数、極性表面積、LogP、水素結合供与体・受容体数などの連続値・整数値で表したもの。各列の物理化学的意味を説明しやすい一方、局所的な部分構造を完全には表現できない。

### フィンガープリント

分子内の部分構造や原子近傍を、固定長のbitベクトルまたはcountベクトルとして表したもの。Morgan fingerprintは代表的な円形フィンガープリントで、原子から一定半径内の環境を符号化する。半径2は概ねECFP4相当であり、2,048 bitなどがよく使われるが、半径や長さはtrain内検証で決める。

参考：[RDKit: Morgan Fingerprints](https://www.rdkit.org/docs/GettingStartedInPython.html#morgan-fingerprints-circular-fingerprints)

### `gap_eV`

今回の回帰目的変数で、単位は電子ボルト（eV）である。QM9にはフロンティア軌道固有値などの電子物性が含まれ、ファイル名とスライドではband gapとして扱われている。今回の `gap_eV` が原QM9のHOMO–LUMO gapをどのように変換・抽出した値かは配布資料に定義がないため、「課題で与えられたエネルギーギャップ」と説明するのが最も安全である。

### MAE

MAEは正解値と予測値の絶対誤差の平均である。

\[
\mathrm{MAE}=\frac{1}{n}\sum_{i=1}^{n}|y_i-\hat{y}_i|
\]

0に近いほど良く、この課題では単位もeVとなる。大きな誤差を二乗するRMSEより外れ値の影響が穏やかで、符号の異なる誤差が打ち消し合わない。

参考：[scikit-learn: mean_absolute_error](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.mean_absolute_error.html)

### NNP

一般にはNeural Network Potential（ニューラルネットワークポテンシャル）を指し、原子配置からエネルギーや力などを予測するモデルである。本課題ではLLMとともにモデルへ組み込むことが禁止されている。略語の主催者定義が別にある可能性は確認する。

## 7. 配布データの実測結果

### 7.1 形状・品質

| 項目 | train | test |
| --- | ---: | ---: |
| データ行数 | 15,000 | 4,000 |
| 列 | `smiles, gap_eV` | `smiles` |
| 欠損セル | 0 | 0 |
| ユニークなSMILES文字列 | 14,998 | 4,000 |
| ファイル内の完全重複行 | 2 | 0 |
| SMILES文字列長の範囲 | 7–27 | 10–28 |
| SMILES文字列長の中央値 | 15 | 15 |
| Fを含むSMILES | 172 | 0 |

trainとtestの間に、完全一致するSMILES文字列は0件だった。ただし、canonical SMILESによる化学構造単位の重複確認はRDKit導入後に行う必要がある。

train内の重複は次の2組であり、それぞれ目的値も同一だった。

| SMILES | 件数 | `gap_eV` |
| --- | ---: | ---: |
| `c1c(ncc(n1)O)C#N` | 2 | 5.23003108 |
| `c1c(ncc(n1)N)CO` | 2 | 4.96335936 |

ランダム分割で同じ分子が学習foldと検証foldへ分かれると、わずかではあるが漏洩になる。canonical SMILESをgroupとして同一foldへまとめるか、完全重複を一意化してから分割する。

### 7.2 目的変数の分布

| 統計量 | `gap_eV` |
| --- | ---: |
| 最小値 | 1.7742 |
| 25%点 | 5.8858 |
| 中央値 | 6.7811 |
| 平均値 | 6.8239 |
| 75%点 | 7.8342 |
| 最大値 | 10.7186 |
| 標準偏差 | 1.2886 |

全trainに対して中央値6.7811を常に予測した場合のMAEは約1.0751 eVである。これはhold-out評価ではなく単純な参考値なので、実際には各foldの学習部分で中央値を計算したbaselineと比較する。

### 7.3 注意すべき分布差

testにはFを含むSMILESが0件だが、trainには172件（約1.15%）ある。さらにtrainのF含有分子は `gap_eV` 平均5.4824 eV、非F分子は平均6.8394 eVで差がある。

この事実だけでF含有行を削除してはいけない。次のように扱う。

- 全trainを使う通常のcross-validationを主評価にする。
- 同じout-of-fold予測について、非F部分だけのMAEも補助評価として出す。
- F含有行を含める／除く最終学習を比較する場合も、testの正解は使わずtrain内検証だけで判断する。
- fingerprint類似度や主要記述子についてもtrain/test分布を比較し、F以外の分布差を確認する。

## 8. 推奨する実施戦略

### Phase 0：ルールを固定する

1. 第5節の曖昧点を主催者へ確認する。
2. 使用可能データ、最大モデル数、正解配布後の操作を短いメモに固定する。
3. 以後の全実験でseed 8、評価指標MAE、同一foldを使う。

完了条件：誰が再実行しても同じ評価条件になる。

### Phase 1：環境とデータ読込を整える

最低限の候補はRDKit、NumPy、pandas、scikit-learnである。XGBoostを候補にする場合だけ追加する。依存バージョンはlock fileで固定し、別lessonの仮想環境は使わない。

読込直後に次をassertする。

- trainは15,000行で列が `smiles, gap_eV`。
- testは4,000行で列が `smiles`。
- `gap_eV` はすべて有限な数値。
- SMILESの欠損がない。
- testの行順を保持する一意な行番号を内部で付ける。

完了条件：全SMILESのparse成否とデータ品質レポートが得られる。

### Phase 2：検証設計を先に固定する

推奨する主検証は5-fold cross-validationである。

1. canonical SMILESをgroupにする。
2. `gap_eV` を分位点でbin化し、可能なら各foldの目的値分布をそろえる。
3. 同じgroupを別foldへ分けない。
4. すべてのモデルで同じfold IDを使う。
5. 前処理、欠損補完、標準化、特徴量選択は各foldの学習部分だけでfitする。
6. 各foldのMAE、平均、標準偏差、全out-of-fold MAEを保存する。

補助評価として、非F行だけのout-of-fold MAEと、Bemis–Murcko scaffoldでまとめた厳しめの分割も確認する。scaffold評価は未知骨格への一般化を見るためで、主スコアと混同しない。

完了条件：定数予測baselineを含む、漏洩のない共通foldが固定される。

### Phase 3：段階的に特徴量を作る

| 特徴量セット | 内容 | 役割 |
| --- | --- | --- |
| D：2D記述子 | 分子量、原子・結合・環数、TPSA、LogP、水素結合関連、部分電荷関連など | 大域的な物性・組成を表し、説明しやすい。 |
| F：Morgan fingerprint | radius 2/3、bitまたはcount、2,048/4,096次元を候補 | 局所的な結合環境・官能基・部分構造を表す。 |
| C：結合特徴量 | DとFを連結 | 大域特性と局所構造を同時に使う。 |

進め方はD → F → Cの順とし、各追加がout-of-fold MAEを改善したか確認する。多数の特徴量を一度に投入して、どの工夫が効いたか分からない状態を避ける。

3D座標は配布されていない。SMILESからのconformer生成と3D記述子は追加候補になり得るが、計算量とseed依存性が増える。まず2D特徴量で完成形を作り、規則上問題ないことを確認した後の追加実験に留める。原QM9の最適化済み3D構造を外部取得してはならない。

### Phase 4：baselineを作る

次の順に作り、パイプラインの誤りを早期に検出する。

1. 各foldのtrain中央値を予測する定数baseline。
2. 標準化した2D記述子によるRidgeまたはHuber回帰。
3. 2D記述子によるRandom ForestまたはExtra Trees。

高度なモデルより先に、データ件数、fold、MAE計算、予測順序が正しいことを確認する。

### Phase 5：最大3系統の有力候補を比較する

候補は、誤差傾向が異なりアンサンブル効果を得やすい構成にする。

| 候補 | 特徴量 | モデル | 狙い |
| --- | --- | --- | --- |
| A | D + F | Extra Trees regressor | 非線形相互作用を捉え、強い古典baselineにする。 |
| B | D + FまたはD | XGBoost regressor | boostingで残差を段階的に改善する。スライドの例とも整合する。 |
| C | F | Tanimoto類似度による重み付きk近傍回帰 | 構造が近い既知分子の物性を使い、木モデルと異なる誤差を得る。 |

候補名は固定ではなく、共通foldで測った結果により入れ替える。例えばSVRが明確に優れるならCと交代してよい。重要なのは、モデル名ではなくout-of-fold MAEと再現性で選ぶことである。

### Phase 6：ハイパーパラメータを調整する

最初は少数の意味のある範囲だけを試す。

- Morgan：radius、bit/count、次元数。
- Extra Trees：木の本数、`max_features`、`min_samples_leaf`、深さ。
- XGBoost：木の深さ、学習率、木の本数、行・列subsample、正則化。
- k近傍：近傍数、Tanimoto類似度の下限、重み関数。

探索時の原則は次の通り。

- MAEを目的関数にする。
- 同一foldで比較する。
- 乱数seedを記録する。
- 試行ごとの平均MAE、fold標準偏差、実行時間、特徴量設定を表に残す。
- 最高値1回だけでなく、fold間の安定性を見る。
- testの正解を探索に一切使わない。

### Phase 7：誤差解析とアンサンブル

各候補のout-of-fold予測について、次を確認する。

- 予測値対実測値と残差分布。
- 低gap・高gap領域ごとのMAE。
- 分子量、重原子数、環数、芳香族性、N/O/F数ごとのMAE。
- trainへの最大Tanimoto類似度と絶対誤差の関係。
- 候補モデル間の残差相関。

単体最良モデルより改善し、複数foldで一貫している場合だけアンサンブルを採用する。重みは非負・合計1を基本とし、out-of-fold予測だけで決める。単純平均より複雑な重みが改善しない場合は単純平均を優先する。

最終予測に使う基モデルは最大3個とする。検証のためのfold別fitが「提出モデル数」に含まれるかは主催者へ確認するが、通常は提出時の予測系統数とは別である。

### Phase 8：最終学習と提出CSVを作る

1. 正解付きtestを見る前に特徴量、モデル、ハイパーパラメータ、重みを凍結する。
2. 選ばれたモデルを全trainで再学習する。
3. 元のtest行順のまま4,000件を予測する。
4. `submission.csv` をindexなしで出力する。
5. 自動検査をすべて通す。

提出形式は次の通り。


### Phase 9：1分説明を準備する

次の型なら、用語と工夫を約1分に収めやすい。

> 配布された15,000分子のSMILESをRDKitで読み込み、分子量や環数などの2D分子記述子と、局所部分構造を表すMorgan fingerprintへ変換しました。外部データや事前学習モデルは使っていません。seed 8の5-fold cross-validationで、同じ分子が学習と検証に分かれないようにし、MAEで比較しました。候補は［モデル名］で、ハイパーパラメータはtrain内のout-of-fold MAEだけを使って選びました。最終的には［単体モデル／最大3モデルのアンサンブル］を用い、検証MAEは［値］eVでした。工夫点は［特徴量の併用／Fを含まない部分の補助評価／アンサンブル重み］です。

## 9. 判断基準

| 判断場面 | 採用基準 |
| --- | --- |
| baselineを卒業する | 共通foldで中央値baselineより明確に低いMAEになる。 |
| 特徴量を追加する | 全out-of-fold MAEが改善し、特定foldだけの偶然でない。 |
| モデルを選ぶ | 平均MAEを第一基準、fold標準偏差、非F部分MAE、計算時間、説明容易性を第二基準にする。 |
| アンサンブルする | 単体最良よりout-of-fold MAEが改善し、残差が十分に異なる。 |
| F含有trainを除外する | 非Fのtrain内検証で一貫した改善がある場合だけ。testにFがないという事実だけでは除外しない。 |
| 外れ値を処理する | 入力・目的値の誤りと確認できない限り削除しない。 |
| 3D特徴量を追加する | 2Dモデル完成後、規則確認済みで、再現可能な改善がある場合だけ。 |
| 最終モデルを固定する | 正解付きtestを見る前。 |

- RDKitで読めないSMILESを記録せず黙って削除する。
- モデル予測を正解に近づけるため手作業で書き換える。

## 13. 推奨する最短ルート

時間が限られる場合は、次の順で進める。

1. RDKit 2D記述子 + Extra Treesで漏洩のない5-fold baselineを完成させる。
2. Morgan fingerprintを追加し、同じfoldで改善を確認する。
3. XGBoostを1系統追加し、単体性能と残差相関を確認する。
4. 単体最良と2モデル平均をout-of-foldで比較する。
5. 改善が再現した方を全trainで再学習し、提出CSVを検査する。
6. 結果を1分説明テンプレートへ反映する。

この順序なら、途中で時間切れになっても有効な単体モデルと提出CSVが残り、その後に精度改善を積み上げられる。
